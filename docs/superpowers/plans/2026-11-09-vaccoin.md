# Vaccoin Implementation Plan

> Execute inline using executing-plans; review whole implementation at the end.

**Goal:** Complete playable, polished 60-second coin vacuum arcade game.
**Architecture:** Separate rendering/assets, arena surfaces, player, coin simulation, vacuum, destruction, effects/audio, Canvas UI, round state, offline Supagame adapter.
**Tech Stack:** Three.js, TypeScript, Vite, Vitest, Playwright.
**Spec:** docs/superpowers/specs/2026-11-09-vaccoin-design.md

## Global constraints
- 10,000–20,000 actual coins, one point each; InstancedMesh and spatial queries.
- 60 elapsed seconds; focus changes cannot extend rounds.
- Three elevations, wide ramps, no snapping through floors.
- Original supplied glTF materials; no asset downloads.
- No invented SDK calls, fabricated standings, or service credentials.

## Review focus
- Floor transitions and underside collision at speed.
- Audio and pointer lock rejection/recovery.
- Hidden tab expiry and restart while submission is pending.
- Local storage unavailable/corrupt.
- Responsive Canvas and large active coin waves.

## Tasks
- [x] 1. Establish config, copied glTF dependency closure, round/state, terrain/player and spatial hash. Tests first for support, ramps, expiry, hash.
- [x] 2. Instanced coin simulation, suction, deterministic population and destructible release. Tests for one-to-one accounting, no duplicates, bounded activity and reset.
- [x] 3. Arena rendering, nozzle/effects, procedural sound, Canvas bitmap UI and complete lifecycle. Browser assertions and visual review.
- [x] 4. Offline adapter with typed future SDK boundary, persistence tests, docs and browser/performance checks. Fresh code review and fix important issues.

## Completion notes

Implemented in the supplied checkout on feat/vaccoin-first-playable. Original assets untouched. User delegated implementation decisions and subsequently approved a new eight-sided collectible. The source KayKit coin remains the emblem; the collectible is a 48-triangle octagon using the same palette. No hosted mutations, publishing, SDK changes, or invented leaderboard data.

Core regression suite covers clock/scoring, seeded reset, spatial queries, both ramp directions, jumps on three floors, ramp undersides, ballistic pillar collisions, nozzle occlusion, pointer-lock intent and storage/integration failures. Whole-implementation review was performed by a separate reviewer; reproduced important findings were fixed and covered by regression tests. Browser and production results are recorded in docs/verification.md.
